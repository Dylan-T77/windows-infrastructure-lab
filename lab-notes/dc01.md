## DHCP Reconstruction Procedure

When rebuilding the full network service stage:

1. Disable the libvirt DHCP service for the isolated lab network so two DHCP servers are not competing.
2. On DC01, open **Server Manager → Tools → DHCP**.
3. Authorize the DHCP server in Active Directory.
4. Create an IPv4 scope appropriate to `192.168.122.0/24`, excluding reserved infrastructure addresses such as `192.168.122.1` and `192.168.122.10`.
5. Configure the default gateway as `192.168.122.1` if the libvirt gateway remains the routed gateway.
6. Configure DNS server `192.168.122.10`.
7. Configure the DNS domain as `corp.lab`.
8. Activate the scope.
9. Renew CLIENT01's lease with `ipconfig /release` and `ipconfig /renew`.
10. Verify that CLIENT01 receives an address from the Windows DHCP scope and uses `192.168.122.10` for DNS.

## File Services Reconstruction

A future file-services stage should use the existing AD security groups rather than assigning permissions directly to individual users.

Recommended structure:

```text
D:\Shares\
├── Common\
├── IT\
└── HR\
```

Suggested access model:

- `IT-Admins`: administrative/full control where appropriate.
- `IT-Users`: access to the IT share.
- `HR-Users`: access to the HR share.
- Common resources should be separated from departmental resources and tested independently.

For SMB shares, configure share permissions and NTFS permissions deliberately, then test effective access with both permitted and denied domain users. Document the results rather than relying only on the intended configuration.
